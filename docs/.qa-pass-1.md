### B4. `recipes-no-json-import` states a bundler limitation that was fixed two months ago — and describes the failure mode incorrectly

**Location:** `docs/internals.md:763-800`, specifically `:773-780` and `:816-820`.

**What the doc says:**

> The store bundler's loader map covers `tsx / ts / jsx / js / css` plus image and font types — but **not** `.json`. … So a JSON import: works perfectly in `npm run dev`; bundles **without an error** in the store build; and hands back **`undefined`** at runtime.
> …
> **Is the caveat still live?** Yes as a bundler fact…

**Evidence** — `conjureos-pack`, `git show 749b7a5`:

```
fix(bundle): support .json imports in the store bundler (0.1.2)

The VFS loader map (and the esbuild loader config) covered ts/tsx/js/jsx/css
and image/font types but omitted .json, so a `.json` import fell back to the
"text" loader: the default export was the raw JSON string and there were no
named exports. …
Add `json: "json"` to the VFS plugin loader map and the esbuild loader config…

 src/bundle/__tests__/json-import.test.ts | 27 +++++++++++++++++++++++++++
 src/bundle/core/bundle.ts                |  1 +
 src/bundle/core/vfs-plugin.ts            |  1 +
```

Dated 2026-06-20, shipped in `@conjureos/pack@0.1.2`, with a committed regression test.

Two separate errors:

1. **The caveat is not live.** `package.json:devDependencies` pins `@conjureos/pack@^0.1.1` — a caret range that resolves to the latest `0.1.x` (`0.1.5` is the newest 0.1 line: `0b64d09 Release 0.1.5`), i.e. **at or above the fix**. CI's `scripts/package.json` pins `^0.2.0`, also above it. Neither path this repo uses is exposed.
2. **The described failure mode is wrong even historically.** It was the *text* loader, not `undefined`: the default export was the raw JSON **string**, and named exports were absent. The regression test's own comment says a named import would make `bundle()` **reject** — contradicting the doc's "bundles without an error." The doc builds its "invisible in every place a developer normally looks" argument on the wrong mechanism.

**Why blocker:** `internals.md` is the source for external developer docs. This publishes a false platform constraint to third parties and tells them to work around a bug that has a regression test guarding against its return. Note #76's checklist says *"the `.json` import caveat **may** still be live; confirm before trimming"* — the doc asserted "yes" without confirming.

**Should say:** the JSON gap was real, was fixed in `@conjureos/pack@0.1.2` (`749b7a5`) with a regression test, and the rule now survives only as history plus a reason to keep pack current. The reason Recipes ships data as `.ts` today is historical, not a live constraint.

### B5. Cross-app section: `importRecipeFromImage` has neither `params` nor `returns`, contradicting the doc's explicit claim

**Location:** `docs/internals.md:439-441`.

**What the doc says:**

> Each carries its own `permission`, a tool-description-grade `description` (this is the orchestrator's *only* routing signal), and JSON-Schema `params` + `returns`.

**Evidence** — `package.json`, `conjureos.actions.importRecipeFromImage` is the complete declaration:

```json
"importRecipeFromImage": {
  "permission": "actions.write",
  "description": "Transcribe a recipe from one or more attached photos … "
}
```

No `params`. No `returns`. The other four actions have both.

Corroboration that this matters: `conjureos-pack/src/validate.ts:508` emits
`conjureos.actions.<key> has no \`returns\` schema — other apps can't discover this action as a data provider (Phase 45 needs↔provides matches on \`returns\`)`. And `validate.ts:496` upgrades it to an ERROR for any app declaring `needs` or run with `--strict`.

**Why blocker:** the doc opens this very section with *"Recipes is the worked example in the external developer docs, so the exact shape matters"* — then states something false about the shape. It also masks a live gap: the fifth action cannot be shape-matched by a Phase-45 consumer, which is the exact capability the same section credits Recipes with providing.

**Should say:** four of five actions carry typed `params` + `returns`; `importRecipeFromImage` (added at `0.10.0`, `ed01bc0`, after the typed-schema pass) declares only `permission` + `description` and is therefore invisible to `needs`↔`provides` shape matching. Flag it as a gap, not a feature.

### S3. A legal section asserts a conclusion of law with no "no counsel has reviewed this" caveat, and is destined for a shipped in-app doc

**Location:** `docs/internals.md:712-716`.

**Evidence:** *"An ingredient list is a statement of fact, not copyrightable expression — Publications International v.
